📚 Theory Reference

All the probability & statistics concepts used in this project.

🎲

Markov Property

The future state depends only on the current state, not the full history.

P(wₙ | w₁,...,wₙ₋₁) ≈ P(wₙ | wₙ₋₁)

This simplification makes language modeling tractable. Bigram uses 1 previous word; trigram uses 2.

📊

Maximum Likelihood Estimation

Estimate probabilities directly from observed counts in training data.

P(w₂|w₁) = Count(w₁,w₂) / Count(w₁)

MLE gives the most likely parameters given the observed data — no priors assumed.

🔧

Laplace Smoothing

Add k to every count to avoid zero probabilities for unseen word pairs.

P(w₂|w₁) = (Count(w₁,w₂) + k) / (Count(w₁) + k·|V|)

Without smoothing, any unseen bigram gets P=0, making perplexity infinite. Laplace fixes this.

🔙

Backoff Strategy

Try trigram first; if data is sparse, fall back to bigram, then unigram.

Trigram → Bigram → Unigram

Higher-order models are more accurate but sparser. Backoff combines their strengths.

📐

Perplexity

Measures how well a model predicts a test corpus. Lower = better.

PP(W) = 2^(−(1/N) Σ log₂ P(wᵢ|wᵢ₋₁))

A perplexity of k means the model is as "confused" as choosing uniformly from k words.

🕳️

Data Sparsity Problem

Most possible n-gram combinations never appear in training data.

Sparsity ≈ 1 − (seen n-grams / |V|ⁿ)

Vocabulary of 500 words → 250,000 possible bigrams but far fewer are observed. Worse for trigrams.

🌲

Trie vs Hash Map (DSA)

Two structures to store n-gram counts with different trade-offs.

Trie: O(m) · HashMap: O(1) avg

Hash maps are faster for lookups on average. Tries save memory on shared prefixes and support prefix search.

📱

Real-World Connection

Your phone keyboard uses exactly this — a statistical language model.

P("world" | "hello") → suggests "world"

Modern keyboards use neural LMs, but the fundamental idea of predicting from context is the same Markov chain principle.
